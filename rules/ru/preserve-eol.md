# Сохранение EOL существующих файлов

В репозитории **у каждого файла свой формат перевода строк** (CRLF или LF). При правке **существующего** файла формат EOL **не менять**.

## ALWAYS

1. **Перед правкой** определи доминирующий EOL файла (по байтам на диске):
   - есть `\r\n` → файл **CRLF**
   - только `\n` → файл **LF**
2. **После любой записи** (MCP `write_module_source`, `StrReplace`, `Write`) проверь EOL. Если изменился — **верни исходный** до завершения задачи.
3. **Не нормализуй** весь файл «для единообразия», если пользователь явно не просил.

## EDT MCP `write_module_source`

Сервер **нормализует `\r\n` → `\n`** при записи. Для файлов с CRLF это ломает diff и EDT.

**Обязательно после `write_module_source`**, если файл был CRLF:

```powershell
$f = 'd:\git\RepEr\src\...\Module.bsl'
$t = [IO.File]::ReadAllText($f) -replace "`r`n","`n" -replace "`n","`r`n"
[IO.File]::WriteAllText($f, $t, (New-Object System.Text.UTF8Encoding $false))
```

Подставь реальный путь. Для LF-файлов постобработка не нужна.

## Новые файлы

Ориентируйся на соседние файлы в той же папке (например, другие `Module.bsl` в `CommonForms/` — чаще CRLF).

## NEVER

- Массовая замена EOL во всём файле как «побочный эффект» правки
- `git add --renormalize` без запроса пользователя
- Считать, что «в проекте один стандарт EOL»
